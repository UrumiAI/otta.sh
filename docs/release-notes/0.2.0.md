# 0.2.0 release notes

0.2.0 of the six `@urumi.ai/otta-*` packages (and `@urumi.ai/otta-store`) was published to npm
on 2026-11-09. There is no CHANGELOG (removed in #451); this file keeps the notes that were
asked for in pull requests and issues, so they are not lost when those close. It lists what an
upgrade from 0.1.0 can break, and what a running store sees. `@urumi.ai/otta-plugin@0.1.0` is
deprecated on npm and points here.

## Breaking for `@urumi.ai/otta-domain` consumers

- **Domain diagnostics go through an injected `logger`, and it is required.** 0.1.0 wrote them
  straight to `console`. In 0.2.0 `logger: Logger` is a required field of these deps types
  (#655, #665):
  - `CartDeps`, `QuoteDeps`, `CreateOrderDeps`, `ExpireOrdersDeps`;
  - `CancelOrderDeps`, `CancelOrderWithRefundDeps`, `FinishCancellationRestockDeps`,
    `RefundOrderDeps`, `SettleDeps`, `LatePaymentDeps`, `ResolveUnverifiedRefundDeps`,
    `CancelDueIntentsDeps`.

  A build fails to compile until each call site passes one. `Logger` is
  `{ info, warn, error }`, each `(message: string, fields?: Record<string, unknown>) => void`;
  a thin wrapper over `console` is enough. To discard diagnostics on purpose, pass
  `NOOP_LOGGER`; both it and the `Logger` type are exported from `@urumi.ai/otta-domain`.
  Adapter authors using the `@urumi.ai/otta-domain/testing` harnesses must include `logger`
  in `settleDeps` and the other deps they build.
- **Two warnings changed shape** (#655). The cart's `addLine` warning ("could not retire an
  out-of-stock claim") had the error message as a string second argument. It now has
  `{ error: { name, code?, message } }`. The coupon `holdsUseUnderKey` warning (new since 0.1.0)
  logs the same described form, not the raw `Error`. The message is cut to 160 characters, and
  quoted runs and email-shaped text in it are replaced with `<value>`. A log filter or test
  that matched the old arguments must change.
- **Cash on delivery** adds order states, payment methods, failure codes, port methods and
  wire fields. The full list is in
  [ADR-0044](../../adr/0044-cash-on-delivery-is-an-offline-payment-method.md), under
  "Breaking for 0.2.0 consumers". It is not repeated here.

## What a running store sees

- **`@urumi.ai/otta-plugin@0.2.0` needs EmDash `^1.3.1`**, and `@urumi.ai/otta-store@0.2.0`
  pins EmDash and `@emdash-cms/cloudflare` at exactly `1.3.1`. See
  [`UPGRADING.md`](../../UPGRADING.md).
- **An unclaimed store needs the setup link** (ADR-0042; the gate is in
  `@urumi.ai/otta-store`'s middleware). From 0.2.0, only the holder of the setup token may
  reach `/_emdash/*` (media reads, plugin routes and the health probe aside) until setup is
  finished. A store that is part-way through EmDash's setup wizard when it upgrades has its
  next setup request refused: the wizard's API calls get `403` with `SETUP_CLAIM_REQUIRED`,
  and the admin pages show "This store hasn't been set up yet". To go on, open the claim link.
  With no `OTTA_SETUP_TOKEN` secret, it is written once to Workers Logs (or the dev server's
  console) in a line tagged `[otta-setup]`. With the secret set, open
  `/_emdash/admin/setup?setup_token=` followed by its value. A store whose setup is already
  finished is not affected.
- **Cash-on-delivery orders hold at most 10 physical items by default** (ADR-0044). Cash on
  delivery is new in 0.2.0, so a store upgrading from 0.1.0 has no such orders; this matters
  to a store that ran a build from `main` before the cap and took larger ones. The setting is
  `settings:codMaxUnitsPerOrder`, **Most items in one order** under **Store settings →
  General → Cash on delivery**. After the upgrade such an order is refused, and the buyer sees
  only "Cash on delivery isn't available for this order right now". Raise the setting, up to
  1000, or set it to 0 for no cap.
